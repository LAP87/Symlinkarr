Setup required

Symlinkarr has no active config.yaml, so it cannot start yet.

No config Config and doctor

Restore from backup

Preferred route when a Symlinkarr backup already exists.

Restore and bootstrap
Docker
Config, database, and secrets are restored on startup.
Mount the backup file into your backup directory and restart the container.
Local
Add --dry-run to preview, --list to inspect the backup first.
symlinkarr restore <path-to-backup.json>

Create a new installation

For a genuinely new install, or a deliberate rebuild from scratch.

Bootstrap
Generates a starter config.yaml and the directories a fresh install needs.
symlinkarr bootstrap
Docker
Skip bootstrap. The compose file already mounts config and data.
Check first
Reports what is missing without creating anything.
symlinkarr bootstrap --list

After either route, restart Symlinkarr, then check Config or Doctor.

What restore can bring back

Restore scope, and what happens automatically at startup.

▾
Included
config.yaml, the SQLite database, tracked symlinks, and config-local secretfiles.
Not included
Add these manually after a restore.
Environment-only secrets and secret paths outside the config directory.
Auto-restore
No manual step needed.
If a backup sits in the default backup directory while config.yaml is missing, Symlinkarr restores it on startup.
